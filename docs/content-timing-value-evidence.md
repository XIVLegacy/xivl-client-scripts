# Content timing and operand authority

A client operand establishes how a supplied value is consumed. A historical
phase limit establishes what its source reported. Neither alone establishes
the runtime producer, admission decision or authoritative outcome.

| Subject | Supported value or consumer | Authority boundary |
| --- | --- | --- |
| Quest phase budgets | Captain's Orders reports 5 minutes for its first bout and 30 for its second. The Call of Nature reports 30 minutes separately for the Morris escort and Dreadwolves fight. | The exact reports and their source hashes belong to `xivl-captures:docs/quest-duty-outcome-evidence.md#reported-phases`. These are historical wiki reports, without reproduced expiry deadlines. Counting updates does not measure elapsed seconds. |
| Warden initializer | Two count segments precede the child `speechType,townType` suffix. One retained record conditionally supplies `(3,2)`. | [Warden initialization](skirmish-behest-client-contract.md#warden-initialization-and-event-operands) owns the positional proof. The retained suffix supplies no per-site town mapping, Join producer or `requestId` binding. |
| Warden event inputs | Join A3/A4 format place/level. Numeric A5 zero selects one presentation arm. End A1/A2 are transport-format operands. | [Event operands](event-command-operands.md#request-warden-binding-and-join-arguments) separate these inputs from widget results and server acceptance. `RequestDirector.requestId` is an independently supplied child field. |
| Guildleve detail | In type 1, evaluation A7 below 1 hides the evaluation UI, and A8 controls stage-icon visibility. | [Type-1 detail payload](guildleve-journal-lifecycle.md#type-1-detail-payload) owns the exact positions. These effects do not supply historical allowance, evaluation or icon producers. |
| Imp question result | The callback compares its sixth argument after self directly with the widget result. Equality returns 0; mismatch returns 1. | [Question arguments and returns](impish-impositions-client-contract.md#imp-question-arguments-and-answer-returns) owns the original instructions. The adjacent five candidate texts do not supply an answer key, selected three-choice order or shuffle rule. |
| Direct repair | Command 24244 takes an equipment-slot integer or bulk selector 27, three nils and a target player control. | [Direct repair issuer](event-command-operands.md#direct-repair-issuer-and-settlement) links the complete nine-position forwarding contract. Its local return does not establish a repair reply, material use, durability or reward settlement. |
| Airship playback | `DftSrt.eventDeparture` calls departure before optional arrival and requests no results from either scene helper. | `xivl-decomp:docs/event/airship-scene-sequence.md#playback-return-and-event-correlation` owns the discarded-return proof. Actor-local notices, helper result pairs and generic event replies do not supply an authenticated booking or invocation discriminator. |

Static marker pairs remain coordinate fields. Their exact values belong to
`xivl-client-data:docs/selected-content-value-rows.md#quest-marker-cells`.
Equality with those fields does not establish a duty origin, return, trigger,
height, facing, radius or private-area type. Likewise, the scene-local marks in
`xivl-decomp:docs/resource/man406-scene-actor-records.md` do not establish world
placements or duty landings.

Named-duty terminal behavior remains canonical in
`xivl-captures:docs/quest-duty-outcome-evidence.md#terminal-fields`.
Grace, failure classification, retry, landing, HP poststate and participant
scope remain independent fields for each duty, phase and trigger. The reported
Morris health clauses are approximate and phase-specific. They establish no
common party-wipe, owner-leave, disconnect or abandonment policy.
